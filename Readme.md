### **Суть работы**

В рамках лабораторной работы были выполнены следующие задачи:

1. **Анализ виртуальной памяти процесса**:

   -  Исследование метрик VSZ, RSS, PSS, USS.

   -  Визуализация карты памяти из `/proc/self/maps`.

   -  Сравнение способов выделения памяти (стек, куча, mmap).

2. **Сравнение методов работы с памятью и файлами**:

   -  Сравнение производительности `mmap()` и традиционного подхода (`read()`/`write()`).

   -  Анализ количества page faults и времени выполнения.

3. **Исследование page faults в реальном времени**:

   -  Выделение большого массива и заполнение его данными с разными паттернами доступа (последовательный и случайный).

   -  Мониторинг minor и major page faults.

4. **Разработка утилиты** `**memory_profiler**`:

   -  Анализ памяти процесса по PID (метрики VSZ, RSS, PSS, USS, карта памяти).

   -  Динамический мониторинг изменений метрик в реальном времени.

   -  Сравнение потребления памяти между процессами.

### **Краткое описание файлов**

#### **Задание A (partA/)**

1. `**memory_info.c**`:

   -  Программа для анализа виртуальной памяти процесса.

   -  Выделяет память разными способами (стек, куча, mmap) и выводит информацию о карте памяти, VSZ, RSS, PSS, USS.

2. `**collect\_**`[`**data.sh**`](http://data.sh):

   -  Скрипт для автоматического сбора данных о метриках памяти и карты памяти.

#### **Задание B (partB/)**

1. `**file_analyzer.c**`:

   -  Программа для сравнения производительности `mmap()` и традиционных системных вызовов (`read()`/`write()`).

   -  Работает с тестовым файлом `testfile.bin` размером 100 MB.

2. `**testfile.bin**`:

   -  Тестовый файл, созданный командой:

      ```bash
      dd if=/dev/urandom of=testfile.bin bs=1M count=100
      ```

#### **Задание C (partC/)**

1. `**page_faults.c**`:

   -  Программа для исследования page faults при последовательном и случайном доступе к памяти.

   -  Выводит количество minor и major page faults.

#### **Утилита** `**memory_profiler**` **(src/memory_profiler/)**

1. `**memory_profiler.c**`:

   -  Утилита для анализа памяти процесса по PID.

   -  Поддерживает три режима работы:

      -  Базовый: вывод метрик памяти и карты памяти.

      -  Динамический мониторинг: обновление метрик каждую секунду.

      -  Сравнение процессов: анализ общего и уникального потребления памяти.

### **Как использовать**

1. **Сборка проекта**:

   ```bash
   make all
   ```

2. **Запуск программ**:

   -  **Задание A**:

      ```bash
      ./partA/memory_info
      ```

   -  **Задание B**:

      ```bash
      ./partB/file_analyzer
      ```

   -  **Задание C**:

      ```bash
      ./partC/page_faults
      ```

   -  **Утилита** `**memory_profiler**`:

      ```bash
      ./memory_profiler <PID>
      ./memory_profiler <PID> --watch
      ./memory_profiler <PID> --compare <PID2>
      ```

3. **Очистка скомпилированных файлов**:

   ```bash
   make clean
   ```

### **Ключевые выводы**

1. **Производительность** `**mmap()**`:

   -  `mmap()` эффективнее для работы с большими файлами благодаря ленивой загрузке и отсутствию лишнего копирования данных.

2. **Page Faults**:

   -  При первом обращении к выделенной памяти происходят minor page faults.

   -  Major page faults возникают только при необходимости загрузки данных с диска.

3. **Метрики памяти**:

   -  **PSS** является наиболее точной метрикой для оценки потребления памяти процессом.

4. **Memory Profiler**:

   -  Утилита предоставляет детальный анализ памяти процесса и позволяет сравнивать потребление памяти между процессами.
